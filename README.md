# nmchv Account

Единый личный кабинет экосистемы nmchv. Это статическое PWA без собственного сервера; авторизация и пользовательские данные подключаются к Supabase.

## Запуск

Откройте каталог через локальный HTTP-сервер, например `python3 -m http.server 8765`, и перейдите на `http://127.0.0.1:8765`. Этот адрес уже разрешён для Supabase Auth. Для настройки Supabase указываются URL проекта и публичный `anon`/publishable key в `scripts/config.js`. Не добавляйте `service_role` и другие секретные ключи.

Кабинет подключён к общему проекту Supabase через публичный publishable key. Перед использованием примените схему в таком порядке:

1. В репозитории [Exam Trainer](https://github.com/nmchv/exam_trainer) выполните `supabase link --project-ref wdijrafblddfcqfbtfmr` и `supabase db push`.
2. В Supabase SQL Editor выполните `supabase/migrations/20261115000000_account_core.sql`.
3. Для админки по очереди выполните `20261115120000_account_admin.sql` и `20261115130000_account_admin_full.sql`, затем назначьте администратора (запрос — в конце первого из этих файлов).

URL для Supabase Auth заданы в `supabase/config.toml`. После настройки DNS примените их командой `supabase config push --remote=wdijrafblddfcqfbtfmr` из этого репозитория. При смене домена обновите `auth.site_url` и `auth.additional_redirect_urls`.

Никогда не помещайте `service_role` key в браузерный код.

## Что реализовано

- Адаптивный кабинет с разделами обзора, проектов, активности, статистики, достижений, целей, уведомлений, профиля и безопасности.
- Реальные операции Supabase Auth: регистрация, вход по паролю, восстановление и смена пароля, выход с текущего или со всех устройств.
- Чтение данных через Supabase с пользовательской сессией; RLS остаётся обязательной границей доступа.
- Единый каталог ссылок на Exam Trainer и GeoTrainer, профиль с общим `auth.users.id`, журнал завершённых попыток Exam Trainer и перенос истории GeoTrainer с выбранного локального профиля.
- RLS-политики и схема кабинета находятся в `supabase/migrations/20261115000000_account_core.sql`.
- PWA-манифест и service worker, кэширующий только статическую оболочку приложения.

## Админка

Кнопка «Админка» в подвале. Администратор видит список всех пользователей, карточку каждого (профиль, статистика, история активности, цели, достижения, уведомления, данные сервисов), выдаёт и отзывает доступы к сервисам, выдаёт достижения, отправляет уведомления и меняет статус и видимость сервисов. Права проверяет Supabase (RLS), а не интерфейс.

## Ограничения интеграции

Импорт истории GeoTrainer в новый проект запускается пользователем при входе и переносит данные выбранного профиля с текущего устройства; источником могут быть и результаты, загруженные в прежнюю базу после входа в старый профиль. Копии с других устройств автоматически не объединяются. Новые сервисы должны явно записывать пользовательские данные в общую схему; общий `service_data` предназначен для простых расширяемых записей, а результаты с серверной проверкой должны иметь отдельные таблицы и Edge Functions. Общий Supabase Auth даёт одну учётную запись, но не бесшовный SSO между доменами: для SSO нужен OIDC-провайдер и отдельная настройка. Edge Functions Exam Trainer нужно опубликовать из его репозитория; приватный `service_role` key хранится только в настройках Supabase.

См. [отчёт аудита](docs/audit.md) и [архитектурные заметки](docs/architecture.md).

## Публикация

Файлы можно размещать на GitHub Pages или любом HTTPS-хостинге статических сайтов. Настройте в Supabase разрешённые redirect URLs и адрес восстановления пароля для итогового домена. Service worker активируется только на HTTPS или localhost.
