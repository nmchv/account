# Предварительный аудит nmchv Account

Дата: 2026-11-08

## Доступные материалы

- Текущий репозиторий `nmchv/account` содержал только пустой README; существующего приложения и локальных миграций здесь нет.
- В публичном репозитории [nmchv/geotrainer](https://github.com/nmchv/geotrainer) обнаружены `auth.js`, `config.js`, `cabinet.js`, PWA-манифест и service worker. Его инструкция описывает установку PWA и push-уведомления.
- В публичном репозитории [nmchv/exam_trainer](https://github.com/nmchv/exam_trainer) есть миграция Supabase, RLS и Edge Functions. Документация описывает защищённые таблицы попыток и серверное оценивание; клиенту запрещено напрямую менять доверенные результаты.
- В [nmchv/web](https://github.com/nmchv/web) используется Astro и Manrope; его README описывает статическую публикацию на GitHub Pages.
- ТЗ задаёт палитру и предполагаемые таблицы Account, но не содержит фактическую схему текущего Supabase-проекта.

## Ограничения и безопасные решения

- Нет доступа к Supabase Dashboard/CLI, секретам окружения, приватным репозиториям, DNS и настройкам хостинга. Нельзя подтвердить, какой проект Supabase общий, какие таблицы уже существуют и какие redirect URLs настроены.
- Поэтому не создавались Supabase-проект, миграции, таблицы, политики, административные роли или Edge Functions. Перед их добавлением нужно сверить фактическую схему и избежать дублирования.
- Схему Exam Trainer нельзя автоматически считать схемой nmchv Account. Её результаты рассчитаны на серверную проверку; кабинет не должен принимать клиентские баллы/XP как доверенные.
- Общий идентификатор Supabase Auth не обеспечивает OIDC SSO между доменами. Передавать токены через URL или вручную между сайтами нельзя.
- Статистика, проекты, достижения и уведомления не заполняются фиктивными записями. До настройки схемы их экран сообщает о проблеме подключения.
- Кабинет пока не перечисляет активные устройства, не предлагает OAuth/passkeys, настройки уведомлений, публичность профиля или административные операции. Эти возможности требуют настроенной схемы и проверенных серверных полномочий.

## Следующие шаги перед эксплуатацией

1. Проверить существующий Supabase-проект, схему, триггеры, RLS и используемый Auth в Geotrainer и Exam Trainer.
2. Согласовать схему Account с существующими таблицами и создать только необходимые аддитивные миграции после проверки.
3. Реализовать доверенный серверный контракт для событий, XP, целей и достижений; клиент не должен сам устанавливать результаты.
4. Определить OIDC-провайдера/поток SSO, настроить redirect URLs, OAuth-провайдеров, домен и DNS.
5. Проверить роли администратора на серверной стороне до появления административных операций в интерфейсе.
